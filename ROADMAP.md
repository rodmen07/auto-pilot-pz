### Figure maintenance: who fixes a number that goes stale between audits (DECIDED 2026-08-08)

**The question, and why it was open.** PR #124's 2026-08-07 product audit wrote *"37 Lua test
suites"*, measured live at `d79e01b`. PR #125 added a 38th suite hours later and did not touch this
file; PR #127 added the 39th. So the figure was wrong by one before that run started and would have
been wrong by two after it. PR #127 adopted a convention to stop that, but adopted it *silently* —
**the pull request that CHANGES a figure this file states corrects that figure, and only that
figure, in the same edit, quoting the superseded wording where it stood, and does NOT restamp the
`Last truth-audited` banner, because it re-measured one number and not the section.** An unrecorded
convention is re-decided by every later slice, so the backlog asked for it to be ratified with a
date or retracted with a reason.

**Decided: ADOPT it — scoped by figure class, which is what the evidence supports rather than a
hedge.** Adherence measured live over the ten commits merged after PR #127 (`6377aa4..fbb0170`), by
comparing each commit's `tests/test_*.lua` count against whether that same commit touched this file:

| Figure | Class | Adherence since PR #127 | Owner |
| --- | --- | --- | --- |
| Lua suite count | glob-derived (one file, one suite) | **4 of 4** — #130 (39→40), #132 (40→41), #133 (41→42), #137 (42→43) each corrected this file in the same commit | the changing PR — and now the guard |
| client module count | glob-derived | guarded since PR #126 | the changing PR — guarded |
| modversion, latest tag | decision-derived (a release) | guarded since PR #126 | the changing PR — guarded |
| assertion total | a SUM over all 43 suites | **0 of 1** — #129 edited two Lua suites, moved the total, and did not touch this file | the periodic product truth audit |
| line counts, commit share | side effects of ordinary work | not tracked | the periodic product truth audit |

**Why the split falls exactly there, and not on "important" versus "unimportant".** A pull request
that adds `tests/test_foo.lua` KNOWS it added a suite: the figure is one `ls` away and the author is
holding the cause in their hand. A pull request that adds three assertions to an existing suite has
no way to notice it moved a whole-tree SUM without re-measuring all 43 suites first. That is the
whole difference between 4-of-4 and 0-of-1, and it is why #129 is not a discipline failure — **a
convention can only bind what its subject can see.**

**The adopted half is now MECHANICAL rather than prose**, because a convention recorded only as a
sentence is the same instrument that already failed here twice: `tests/test_roadmap_truth.py` takes
the suite count as its fourth guarded claim, bound to the `tests/test_*.lua` glob with the same
exactly-once anchor discipline as the other three (zero matches and duplicate matches are both hard
failures, so a reworded claim cannot silently blind it). This CORRECTS PR #126's own scoping, which
excluded *"line counts, suite and assertion totals, and commit share"* as a single group on the
grounds that guarding them *"would redden unrelated work daily and be switched off"*. That reasoning
is still right and is exactly why the assertion total stays out — but it never described the suite
count, which moves on a deliberate act and reddens only the pull request already responsible for it.
The line PR #126 itself drew — *guard what changes on a deliberate, dated decision (a release, a
module added or deleted); audit what changes as a side effect of ordinary work* — put the suite
count on the guarded side all along; only the grouping in its exclusion list disagreed.

**Overridable default, reversible in one word.** If the user would rather this file carried no
suite-count figure at all, deleting the claim is the cheaper fix and the guard fails loudly (zero
anchor matches) rather than silently the moment it goes, which is the signal to remove the guard in
the same edit. Retracting the convention instead means naming an audit cadence in its place; nothing
here depends on the convention except this file's own freshness between audits.
